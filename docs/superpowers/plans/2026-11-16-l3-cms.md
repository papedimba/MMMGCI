# Lot L3 — CMS — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Permettre au personnel désigné de gérer sans développeur le contenu du site public : pages à blocs, menus, articles, événements, documents officiels, galeries, bannières, témoignages, médiathèque, réglages du site et boîte des formulaires reçus, avec un circuit de publication (le rédacteur soumet, un détenteur de `cms.publish` publie).

**Architecture:** Module `app/Modules/Cms/` (services + contrôleurs, même découpage que `Members`), migration 0016. Les pages sont composées de **blocs structurés** d'un registre fixe (validation et rendu PHP) ; le seul HTML libre est celui du bloc « texte » et des corps d'articles, produit par un éditeur riche minimal et **nettoyé côté serveur** (`HtmlSanitizer`). Le rendu public est le lot L4 : L3 ne sert que l'administration et fournit les services de lecture (`PublishedContent`) que L4 consommera.

**Tech Stack:** PHP 8.2 sans framework, MariaDB/MySQL (PDO), PHPUnit, un seul fichier JavaScript d'éditeur (externe, CSP), aucune dépendance.

**Spec:** `docs/superpowers/specs/2026-11-16-site-public-cms-design.md` (choix par défaut), `docs/conception/04-base-de-donnees.md` §3.2, `03-architecture.md` (A2 arborescence, A5.5 publication éditoriale), `06-plan-taches.md` (L3, T3.1–T3.9).

## Global Constraints

- PHP ≥ 8.2, `declare(strict_types=1)`, aucune dépendance Composer en production ; requêtes préparées ; migration 0016 (jamais modifier une migration appliquée) ; Africa/Abidjan ; français ; CSP stricte (aucun style/script en ligne) ; kit `ui()` ; une `h1` ; cibles ≥ 44 px au toucher ; téléphone d'abord.
- **Jamais de contenu inventé** : aucune page, aucun texte ni aucune image n'est créé par le code sauf ce que le lot L4 sème **en brouillon** à partir du cahier des charges. Coordonnées et réseaux sociaux = réglages vides par défaut.
- **Un brouillon n'est jamais public** : aucun service de lecture publique ne renvoie un contenu qui n'est pas `publie` (ou `programme` dont la date est échue) ; archivé = non public.
- **Sécurité du contenu riche** : tout HTML saisi passe par `HtmlSanitizer::clean` à l'enregistrement ET le rendu public échappe tout le reste ; aucune balise `script`, aucun gestionnaire `on*`, aucun `style`, aucune URL `javascript:`/`data:` ; liens externes en `rel="noopener noreferrer"`.
- **Médias** : liste blanche (`Uploads` profils `image` et `document`), **pas de SVG téléversé**, texte alternatif obligatoire pour toute image, nom de fichier jamais conservé tel quel sur disque ; les médias publics vont dans `public/media/` (interdit d'exécution via `.htaccess`).
- **Séparation des fonctions** : `cms.pages.manage` crée/modifie/soumet (jamais publie) ; `cms.publish` publie, programme, archive ; `cms.media.manage` médiathèque ; `cms.forms.manage` formulaires reçus ; `cms.settings.manage` réglages du site. Chaque transition de publication est auditée.
- **Slugs** : `[a-z0-9-]`, 1 à 80 caractères, uniques ; les slugs réservés `admin`, `verifier`, `espace`, `assets`, `media`, `sante`, `adhesion-en-ligne`, `sitemap.xml`, `robots.txt`, `favicon.ico` sont refusés ; la hiérarchie donne l'URL `/{parent}/{enfant}`.
- Toute route `/admin` : `[$requireAuth, $permission('x')]` ; `AdminRouteSweepTest` reste vert ; la suite existante (640 tests) reste verte, aucune assertion affaiblie ; chaque écriture est auditée.

## Review Focus

1. **XSS et contournement du nettoyage** : balises imbriquées, entités, `<svg>`, `<math>`, `<a href="jav&#x61;script:">`, attributs `srcset`, `style`, `formaction`, HTML déformé, très grande profondeur ; texte des blocs (titres, libellés, alt) échappé à l'affichage.
2. **Fuite de brouillon** : un brouillon, une page archivée ou programmée dans le futur apparaît-il dans un menu, une liste, un lien direct, le sitemap, la recherche ou une API ?
3. **Escalade de rôle** : un rédacteur peut-il publier par un POST forgé, modifier l'état d'une page déjà publiée sans repasser en relecture, ou supprimer un contenu publié ?
4. **Médias** : fichier déguisé (polyglotte, extension double, `.php`, SVG renommé), image géante (bombe de décompression), nom hostile, suppression d'un média encore utilisé par une page publiée.
5. **Hiérarchie et slugs** : cycle parent→enfant, slug réservé, collision, changement de slug d'une page publiée (ancien lien cassé : redirection ou refus ?), suppression d'un parent.

## Rulings de conception (à confirmer par la Mutuelle)

- Le CMS n'a pas de constructeur visuel libre : blocs d'un registre fixe + éditeur riche limité.
- Publier est séparé de rédiger (déjà décidé en conception A5.5) ; un rédacteur ne publie jamais.
- Les coordonnées publiques exigent une **validation** comme tout paramètre : elles n'apparaissent pas sur le site tant qu'elles ne sont pas validées.
- Les témoignages sont désactivés tant que le consentement n'est pas joint et que le réglage n'est pas validé.
- Aucune purge automatique des formulaires reçus (durée de conservation non définie).
